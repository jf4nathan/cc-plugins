# LLM Headline Setup

statusplus can print a one-line "newspaper headline" summary of the current Claude Code conversation on line 3 of the statusline. This is **opt-in** — without running this skill the statusline behaves exactly as before. The summary refreshes asynchronously (background subprocess), so the statusline itself stays fast.

## Privacy notice — read first

The headline is generated by sending the **opening session transcript window, anchored at session start and capped at 12,000 characters,** to an LLM API. Treat this as outbound network traffic from the user's machine on every cache-miss render (default: every 60 seconds while the session is active).

| Provider choice | What it means for the user's data |
|---|---|
| **Anthropic** | Same trust surface as Claude Code itself. The transcript already goes here. Recommended for users in regulated contexts (HIPAA, etc.). |
| **OpenAI-compatible** (OpenAI, OpenRouter, Groq, local Ollama, custom) | Transcript content is sent to a new provider. **Mention this explicitly to the user** before storing the key — they may not have realized the headline feature implies leaving the Anthropic trust boundary. For local Ollama, no data leaves the machine. |

If the user works in a HIPAA / regulated environment and is unsure, recommend Anthropic. Do not silently pick OpenAI.

## Steps

Run these in order. Each step is interactive — wait for the user's reply before moving on.

### 1. Check current state

Detect whether a config already exists and report it back.

```bash
python3 - <<'PY'
import json, os, pathlib
p = pathlib.Path(os.path.expanduser("~/.claude/.statusplus/config.json"))
if not p.exists():
    print("NOT_CONFIGURED")
else:
    try:
        cfg = json.loads(p.read_text(encoding='utf-8'))
        # Redact the key for display.
        k = cfg.get('api_key') or ''
        cfg['api_key'] = (k[:6] + '...' + k[-4:]) if len(k) > 12 else '***'
        print("EXISTING_CONFIG")
        print(json.dumps(cfg, indent=2))
    except Exception as e:
        print(f"BROKEN_CONFIG: {e}")
PY
```

- If `NOT_CONFIGURED`: go to step 2 (fresh setup).
- If `EXISTING_CONFIG`: show the user the redacted config and ask:
  > A config already exists. What do you want to do?
  > 1. Reconfigure (replace it)
  > 2. Disable the headline (delete config + clear cache)
  > 3. Cancel
- If `BROKEN_CONFIG`: show the error and ask whether to replace it.

### 2. Pick a provider

Ask:
> Which provider should generate the headline?
> 1. Anthropic (same trust surface as Claude Code — recommended)
> 2. OpenAI-compatible endpoint (OpenAI, Groq, OpenRouter, local Ollama, custom)
> 3. Cancel

**If the user picks #2**, surface the privacy warning explicitly and require a second confirm:
> Heads up: this will send the opening session transcript window, anchored at session start and capped at 12,000 characters, to that endpoint on every refresh. If you work with regulated data (PHI, PII, customer secrets, etc.), confirm this is OK before continuing.
> 1. Yes, I understand — continue with OpenAI-compatible
> 2. Switch to Anthropic
> 3. Cancel

Only proceed if the user explicitly accepts.

### 3. Gather settings

For **Anthropic**, ask in sequence:
- API key (paste). If the user says they don't have one, tell them to create one at https://console.anthropic.com/settings/keys — the Claude Code subscription does not include API-console credit.
- Model — default `claude-haiku-4-5-20251001`. Offer to use the default or paste a different model id.

For **OpenAI-compatible**, ask in sequence:
- Endpoint URL (full path to the chat-completions endpoint). Defaults to suggest:
  - OpenAI: `https://api.openai.com/v1/chat/completions`
  - Groq: `https://api.groq.com/openai/v1/chat/completions`
  - Ollama (local): `http://localhost:11434/v1/chat/completions`
- API key (paste). For local Ollama, accept any non-empty string (e.g. `ollama`) — the API requires a header but ignores the value.
- Model — ask for the model id (e.g. `gpt-4o-mini`, `llama-3.1-8b-instant`, `llama3.2:1b`).

### 4. Write the config

```bash
python3 - <<'PY'
import json, os, pathlib, sys

provider = sys.argv[1]            # "anthropic" or "openai"
endpoint = sys.argv[2]            # full URL
api_key  = sys.argv[3]
model    = sys.argv[4]

cfg = {
    "provider": provider,
    "endpoint": endpoint,
    "api_key": api_key,
    "model": model,
    "max_tokens": 50,
    "timeout_s": 8,
    "cache_ttl_s": 60,
}
p = pathlib.Path(os.path.expanduser("~/.claude/.statusplus/config.json"))
p.parent.mkdir(parents=True, exist_ok=True)
p.write_text(json.dumps(cfg, indent=2) + "\n", encoding='utf-8')
try:
    p.chmod(0o600)
except Exception:
    pass
print(f"Config written: {p}")
PY
```

Pass the four values as positional args. Quote them. **Never echo the API key back to the user in the terminal output.**

### 5. Run a one-shot connectivity test

Verify the API call reaches the provider before declaring success. Note: passing an empty transcript path causes the script to return immediately before contacting the provider — use the explicit HTTP check below to confirm auth and network reachability.

```bash
echo '{"session_id":"statusplus-llm-setup-test","transcript_path":""}' \
  | python3 "$HOME/.claude/bin/llm-summary.py" --refresh
```

To check for HTTP-level failures explicitly:

```bash
python3 - <<'PY'
import json, os, pathlib, urllib.request, urllib.error
cfg = json.loads(pathlib.Path(os.path.expanduser("~/.claude/.statusplus/config.json")).read_text())
provider = cfg.get('provider')
try:
    if provider == 'anthropic':
        req = urllib.request.Request(
            cfg['endpoint'], method='POST',
            data=json.dumps({"model": cfg['model'], "max_tokens": 5, "messages": [{"role": "user", "content": "ping"}]}).encode(),
            headers={'Content-Type':'application/json','x-api-key':cfg['api_key'],'anthropic-version':'2023-06-01'},
        )
    else:
        req = urllib.request.Request(
            cfg['endpoint'], method='POST',
            data=json.dumps({"model": cfg['model'], "max_tokens": 5, "messages": [{"role": "user", "content": "ping"}]}).encode(),
            headers={'Content-Type':'application/json','Authorization':f'Bearer {cfg["api_key"]}'},
        )
    with urllib.request.urlopen(req, timeout=8) as r:
        print("OK", r.status)
except urllib.error.HTTPError as e:
    body = e.read().decode('utf-8', 'replace')[:400]
    print(f"HTTP {e.code}: {body}")
except Exception as e:
    print(f"ERROR: {type(e).__name__}: {e}")
PY
```

If the test prints `OK 200`, the wiring works. If it prints `HTTP 401` / `HTTP 403`, the key is wrong — offer to redo step 3.

### 6. Tell the user what to expect

> Configured. The headline will appear on line 3 of the statusline within ~60 seconds of your next Claude Code response. The first render after a fresh session is empty because there's nothing to summarize yet.
>
> To change settings later: `/statusplus:statusplus-llm-setup` again and pick "Reconfigure".
> To disable: `/statusplus:statusplus-llm-setup` and pick "Disable".

## Disabling (reached from step 1, option 2)

```bash
rm -f "$HOME/.claude/.statusplus/config.json"
rm -rf "$HOME/.claude/.statusplus/cache"
echo "LLM headline disabled. Config and cache removed."
```

The statusline will stop printing line 3 on the next render. Nothing else changes.

## How the headline is generated

The script builds a single opening window from the transcript:

- The window is capped at **12,000 prefixed characters** total. Individual message text is capped at **800 characters** before being added to the window.
- The final headline is capped at **14 words**.
- The headline is stored in `~/.claude/.statusplus/cache/<sid>.summary`.
- Once a full opening window has been successfully summarized, a `<sid>.full` marker file is written. While `<sid>.full` exists, the script skips the LLM call and serves the cached headline directly — preventing unnecessary refreshes.
- Fallback transcripts (e.g. when the transcript file is missing or unreadable) may populate the cache with an empty or generic result, but they do **not** create `<sid>.full`, so a real summary can still be generated on the next refresh.

To change settings or disable the feature: `/statusplus:statusplus-llm-setup` again.

## Files this skill touches

| Path | Purpose |
|---|---|
| `~/.claude/.statusplus/config.json` | Provider, endpoint, key, model, tunables. `chmod 600`. |
| `~/.claude/.statusplus/cache/<sid>.summary` | Cached headline per session. `chmod 600`. Refreshed in background by `~/.claude/bin/llm-summary.py`. |
| `~/.claude/.statusplus/cache/<sid>.full` | Marker written after a successful full opening-window summary. Prevents re-summarizing a frozen session. |

The helper script `~/.claude/bin/llm-summary.py` is deployed by `/statusplus:statusplus-setup` and refreshed by `/statusplus:statusplus-update` — this skill assumes it's already present.

## Tunable fields in config.json

| Field | Default | Description |
|---|---|---|
| `cache_ttl_s` | `60` | Seconds before the headline is refreshed in the background. |
| `max_tokens` | `50` | Token budget for the LLM response. |
| `timeout_s` | `8` | API call timeout in seconds. |
